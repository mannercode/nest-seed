# 재사용 핵심 기능 TODO

사용자·인증·권한·파일 관리를 여러 프로젝트에서 사용할 핵심 기능으로 다듬는다. 각 기능이 보장할 동작과 실패 처리를 기준으로 완성도를 높이고, 영화·상영·예매 예제의 기능 확장은 분리한다. 재사용한다는 이유만으로 코드를 `libs/`로 이동하지 않는다.

| 인증      | [authentication.md](authentication.md) | 비밀번호, 로그인 제한, 토큰·세션, 계정 복구             |

`검증 우선`은 코드에서 확인한 경로를 재현하고 기존 계약의 불일치를 수정할 작업이다. `결정 필요`는 API·데이터·보안 정책을 확정한 뒤 구현할 작업이다. 별도로 재현을 명시한 항목 외에는 코드와 기존 테스트를 읽고 정리한 계획이며, 결함 재현이나 전체 검증을 마쳤다는 뜻이 아니다.

## 진행 순서

1. 인증 A1의 비밀번호 경계를 처리하고, 인증 A2와 파일 F2~F4의 부분 실패·경합을 재현한다.
2. 사용자 U1·U2·U4, 인증 A3·A4, 권한 R3, 파일 F1·F5의 정책을 정한다. 세션 회수와 파일 삭제의 완료 기준은 관련 수정 전에 확정한다.
3. 정해진 계약에 맞춰 구현한다. 사용자 U3과 인증 A5는 실제 메일 발송 수단과 복구 정책이 정해진 뒤 진행한다.

## 공통 작업

- [ ] [영역별 검토 기준](../docs/reference/project-review.md)과 [시드의 범위](../docs/reference/decisions.md)에 사용자·인증·권한·파일 관리를 재사용 핵심 기능으로 명시하고, [README](../README.md)의 제공 범위를 맞춘다. 현재 `apps/` 전체에 적용하는 예제 중심 기준을 기능의 목적에 따라 구분한다.

각 항목의 구현에는 관련 DTO·설정·API 사용 예시·문서와 기존 테스트의 갱신을 포함한다. 검증 범위와 테스트 작성은 [개발 규칙](../docs/reference/conventions.md), 완료 항목 삭제는 [TODO 관리](../docs/reference/project-review.md#todo-관리)를 따른다. 새 테스트 파일이 필요하면 저장소 지침에 따라 먼저 동의를 받는다.

## 보류

소셜 로그인·MFA·패스키, 조직·멀티테넌트 권한, 범용 권한 엔진, 미디어 변환·파일 버전 관리는 구체적인 사용처가 정해질 때까지 완료 조건에서 제외한다. 메일은 계정 확인·복구에 필요한 범위부터 검토하며 알림 제품 전체로 확장하지 않는다.
