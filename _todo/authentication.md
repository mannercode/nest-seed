# 인증

현재 Argon2id 비밀번호 비교, 역할별 JWT, DB 인증 버전 확인, Redis refresh 토큰 회전·폐기, IP별 로그인 실패 제한, BFF 쿠키 처리가 있다. 기존 계정·해시의 마이그레이션은 시드의 작업 범위에 포함하지 않는다.

## 최소 기본값 정리

### A1. 비밀번호 입력 정책

- [ ] 시드의 최소·최대 길이와 문자 수 계산·공백 처리 기본값을 정하고 기존 생성·변경·로그인 경로에 일관되게 적용한다.

근거: 사용자·관리자 생성·변경 DTO와 [관리자 생성 스크립트](../apps/api/scripts/admin-create.cjs)는 최소 1자만 검사하고 로그인 DTO는 문자열 여부만 검사한다. [PasswordHasher](../libs/common/src/auth/password.ts)는 Argon2id로 원문 전체를 처리하므로 bcrypt의 72바이트 한도를 입력 정책으로 사용할 이유는 없다.

최소 범위: HTTP 본문 크기 제한과 비밀번호 최대 길이를 구분하고, 입력을 조용히 자르거나 trim하지 않는다. 가입 화면·DTO·독립 관리자 스크립트에 같은 기준을 적용한다. 앱의 입력 기준을 재사용 해시 함수에 강제하지 않으며, 복구 기능을 새로 만들지는 않는다. 이메일 식별은 [사용자 U2](users.md)와 함께 맞춘다.

검증: ASCII·한글·이모지·공백의 경계값과 생성·로그인·변경 간 일관성을 확인한다. 허용된 긴 비밀번호의 끝부분까지 비교하는 기존 테스트를 유지한다.

## 서비스별 확장 보류

### A3. 토큰·세션 정책 확대

보류 이유: [현재 계약](../apps/README.md#http와-인증-계약)은 access JWT를 최대 5분간 허용하며 계정 상태를 매 요청 조회하지 않는다. refresh 유효 기간은 7일이고 갱신할 때 연장된다. 교체된 토큰은 409로 거절하고 현재 세션은 유지한다. 이 동작을 시드의 기본으로 유지하며, 즉시 회수·세션 최대 수명·관리자 전체 로그아웃은 실제 서비스의 요구가 있을 때 추가한다.

재검토 조건: 로그아웃·비밀번호 변경·계정 정지·탈퇴의 효력 시점이나 토큰 재사용 정책을 바꿀 필요가 생기면, 상태 조회 비용·저장소 장애 시 동작·정상 동시 요청과의 구분을 함께 정한다. 사용자·관리자의 만료·회수·동시 갱신과 BFF 쿠키 처리를 검증한다. 기존 5분 허용·409 기대값은 계약 변경을 결정한 경우에만 바꾼다.

### A4. 로그인 제한 정책 확대와 배포 프록시 구성

보류 이유: [현재 제한](../apps/api/src/services/gateway/login-rate-limiter.service.ts)은 IP별 실패 50회, 첫 실패부터 15분 만료이며 성공해도 초기화하지 않고 두 역할이 집계를 공유한다. 이를 유지하고 계정 잠금·해제나 역할별 제한을 추가하지 않는다. [BFF의 전달 헤더 신뢰 조건](../apps/README.md#데모와-bff)은 배포 구성이 정해져야 적용할 수 있다. 기본 설정에서는 여러 사용자가 BFF 주소 하나로 보일 수 있고, 브라우저 테스트는 실제 배포 edge를 검증하지 않는다.

재검토 조건: 실제 서비스에 IP·계정별 제한 조합이 필요하면 같은 IP의 정상 사용자, 여러 IP의 동일 계정, 타인의 반복 실패로 잠긴 계정의 해제 방법을 정한다. 실제 IP를 확정하는 프록시를 지정하고 위조·누락 헤더와 직접 접근 경로를 검증한다. 한도·만료·해제·역할별 공유 조건을 바꾸면 미등록 계정·동시 실패·Redis 장애도 확인한다.

### A5. 비밀번호 변경 재인증·분실 복구

보류 이유: 현재 본인·관리자 수정 DTO로 새 비밀번호를 저장할 수 있으며 현재 비밀번호 재확인과 분실 복구는 제공하지 않는다. 재인증 방식과 계정 복구는 서비스 정책과 실제 메일 발송 수단이 필요하므로 시드 완료 조건에서 제외한다.

재검토 조건: 도입할 서비스에서 본인 변경의 재인증·관리자 변경 권한과 복구 정책을 정하고 [사용자 U3](users.md)의 이메일 확인·발송 수단을 확보한다. 복구 토큰의 일회성·만료·재발급, 미등록 계정 응답·재발송 제한, 복구 후 세션 처리를 정한다. 틀린 현재 비밀번호, 토큰 만료·재사용·동시 사용, 발송 실패와 복구 후 이전 비밀번호·세션의 동작을 검증한다.
