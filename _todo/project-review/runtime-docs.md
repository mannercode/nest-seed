# 실행 환경·설정·문서 검토

기준은 `6bbe8cdf7df05ce9aa69cd6ab116f8ccde3fb7f0`이다. 담당 87개 파일 중 사람이 작성한 텍스트는 전체를 읽었고, 생성된 `pnpm-lock.yaml`은 두 YAML 문서의 모든 importer·package·snapshot을 구조적으로 검사했다. 전체 범위와 다른 영역의 발견은 [통합 결과](README.md)를 따른다.

이 문서의 발견과 선택적 정리는 모두 보류한다. 재현·대조 근거를 남기는 참고 자료이며, [진행할 5개 작업](README.md)의 완료 조건에 포함하지 않는다.

## R1 · 보류 — 로그인 제한 주석이 현재 정책과 다르다

- 근거: [.env.api](../../.env.api) 18행은 계정별 실패 5회와 IP별 실패 50회를 함께 설명한다. 실제 [LoginRateLimiterService](../../apps/api/src/services/gateway/login-rate-limiter.service.ts) 27–43행은 IP 해시별 카운터만 사용한다. [앱 가이드](../../docs/apps.md)는 이메일별 잠금을 구현하지 않는다고 설명한다.
- 영향: 포크한 사람이 없는 계정별 제한을 기대하거나 해당 설정을 찾게 된다. 현재 인증 동작의 결함은 아니다.
- 수정 후보(보류): 주석을 실제 IP별 제한과 만료 시점에 맞춘다. 계정별 제한 기능을 새로 추가할 이유는 없다.
- 검증: env·Config·호출 구현·현행 가이드 대조. 확신 높음.

## R2 · 보류 — 사용하지 않는 버전별 설치 예외가 남아 있다

- 근거: [pnpm-workspace.yaml](../../pnpm-workspace.yaml) 25–42행의 `minimumReleaseAgeExclude` 17개 중 15개는 현재 lockfile에 없다. AWS SDK 3.1131.0, Next 16.3.5와 그 플랫폼 패키지, Nest schematics 12.0.1, Zod 4.6.2가 해당한다. 현재 남은 일치 항목은 compression 1.8.2와 lint-staged 17.5.1이다.
- 영향: 현재 설치를 깨지는 않지만, 과거 한시적 예외와 지금 필요한 설정을 구분하기 어렵다.
- 수정 후보(보류): 더 이상 참조되지 않는 정확한 버전 항목만 정리한다. 다른 OS의 설치 스크립트 허용 항목이나 현재 사용 중인 예외를 일괄 삭제하지 않는다.
- 검증: YAML을 파싱해 lockfile의 전체 package key와 대조. 확신 높음.

## 시드 관점의 선택 검토

### S1 — 개발 환경의 개인 도구 설정

[devcontainer.json](../../.devcontainer/devcontainer.json) 28–39행은 Codex·GitHub CLI의 호스트 설정과 Codex 상태 디렉터리를 기본으로 마운트한다. 현재 개발자의 작업 방식에는 맞고 필요한 디렉터리도 생성한다. 다만 처음 포크하는 사람은 NestJS 실행과 별개인 도구 설정까지 읽게 된다.

현재 구성을 유지하거나, 개인 도구 마운트·링크만 로컬 customization으로 분리할 수 있다. 후자는 시드 기본 설정을 줄이지만 지금의 즉시 사용 편의가 줄어든다. 보안 기능 추가나 개발 경로 전체 교체를 권하는 항목은 아니다.

### S2 — 재사용 조건을 찾는 진입점

[루트 manifest](../../package.json)에는 `license: MIT`가 있지만 기준 커밋의 추적 파일에는 독립 `LICENSE`가 없다. 외부에 시드를 배포할 목적이라면 작성자가 의도한 라이선스 원문과 표시 정보를 확인할 위치를 마련하는 편이 명확하다. 작성자·권리 정보를 추정해서 문서를 생성하지 않았으며, 법적 적합성을 판정한 결과도 아니다.

### S3 — 실행 부담과 변경 범위

MongoDB 3노드·Redis 3노드·S3·NATS·Restate, 단일 Dev Container 경로, 4개 API 복제본과 반복 CI는 현재 확인하려는 분산 계약과 연결돼 있다. 서비스 개수나 테스트 횟수만으로 제거 대상으로 판정하지 않는다. 처음 사용하는 사람의 준비 부담은 여전히 있으며, README의 단순 CRUD부터 읽는 순서가 이를 일부 보완한다.

정기 버전 갱신은 계약·구조 수정과 별도 PR로 유지하는 편이 원인 추적에 유리하다. 현재 Dependabot의 생태계별 그룹은 그 방향에 맞는다. 이번 리뷰에서 도구 교체·major 갱신·추가 실행 모드를 요구하지 않는다.

## 유지가 적절한 구성

| 영역                | 판단 근거                                                                                                                                                                                               |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 루트 명령           | build·lint·test·실행 가능한 문서의 진입점이 분명하다. workspace 스크립트의 타입·코드·설정 검사도 연결돼 있다.                                                                                           |
| Docker·env          | Node·pnpm 버전과 이미지 digest를 고정한다. 생성 시 env 주입, 동일 절대경로 bind, raw env 전달이 코드와 가이드에 일치한다.                                                                               |
| Dev Container reset | 데이터 삭제는 강한 제약이지만 명시한 개발 계약이다. 이번 리뷰에서는 reset을 실행하지 않았다.                                                                                                            |
| TypeScript 변환     | TSC 개발 경로, Rspack 배포 경로, Vitest의 metadata 변환은 실행 목적이 다르다. 생성된 decorator fallback만 coverage 제외하는 조건도 확인했다.                                                            |
| pnpm lock           | 도구 자체와 workspace 의존성의 두 문서, workspace importer 11개, package 955개·snapshot 956개를 검사했다. manifest 불일치·끊긴 전이 참조·integrity 누락은 없었다. npm alias 3개도 실제 대상에 연결된다. |
| Nest peer           | common/core/platform-express/testing이 각 한 버전으로 해석된다. TypeScript 6.0.3과 7.0.2의 용도별 고정은 유지한다.                                                                                      |
| CI                  | 필수 AtoZ와 반복 Stability·Race의 역할이 구분돼 있다. 확인한 자동 merge 실패는 PR 충돌이었고 후속 갱신에서 성공했다. 보호 검사를 우회한 사례로 판단하지 않는다.                                         |
| 문서 위치           | `docs/*.md`는 대응 폴더의 안내, `docs/reference/`는 공통 규칙·선택 이유를 소유한다. 현재 문서의 SoLA·controller 순환·네이밍 설명은 구체적인 코드와 연결된다.                                            |
| 문서 링크 검사      | 루트 `*.md`와 `docs/**/*.md`만 검사한다. `_todo`를 정규 검사에 추가하지 않았다. 과거 가이드 원문 제외 패턴은 현행 안내 파일을 제외하지 않는다.                                                          |

## 실제 실행과 한계

루트 `pnpm run lint`가 통과했고, 문서 링크 검사 110건 중 오류는 0건이다. Compose 네 진입점도 `config --quiet`를 통과했다. 전체 단위·통합 테스트, 브라우저 E2E와 API 문서 실행 결과는 [통합 결과](README.md)에 모은다.

외부 SDK의 전체 소스, 이미지 내부 모든 패키지와 모든 플랫폼에서의 새 설치를 감사한 결과는 아니다. 인프라 reset·Restate SIGKILL 회귀·장시간 race·benchmark·반복 CI를 이 로컬 커밋에서 새로 실행하지 않았다. 조회한 원격 실행의 커밋과 이번 검토 기준 커밋은 구분한다.
