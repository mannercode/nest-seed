# 프로젝트 검토의 남은 항목

[README의 영역별 변경·검토 기준](../../README.md#기능코드-변경-시-주의사항)을 따른다. 공유 라이브러리의 계약 오류는 현재 시드의 사용 여부로 보류하지 않는다. 아래에는 미처리 작업과 미결 판단만 둔다.

## 보류한 발견과 정리

보류는 다음 순서의 필수 작업을 뜻하지 않는다. 재검토 조건이 생기면 실제 영향과 변경 비용으로 범위를 정한다.

| 항목                                                        | 보류 이유·재검토 조건                                                                                   | 상세                                                           |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| API 테스트의 부분 초기화 실패                               | 테스트 수명 정리 시 취득한 자원의 소유·종료 경계를 함께 확인한다.                                       | [TD-02](tests-demos.md)                                        |
| 표현할 수 없는 소수 상영 시간                               | 예제에서 지원할 시간 단위를 정할 때 스키마와 계산 범위를 맞춘다.                                        | [API-4](api.md)                                                |
| 작은 내부 DTO·결과 타입 파일                                | 동작 결함은 아니다. 해당 코드를 정리할 때 별도 파일이 줄이는 혼동과 탐색 비용을 비교한다.               | [API](api.md)                                                  |
| 추가 단언·반복 fixture·barrier·업로드 타이밍·benchmark 경계 | 검증 경로와 실제 실행 비용을 확인한 뒤 필요한 범위만 보완한다.                                          | [테스트·데모](tests-demos.md), [라이브러리 추가 조건](libs.md) |
| 같은 Mongo collection의 서로 다른 index 선언                | 여러 저장소의 다른 선언을 지원할지와 초기화 소유권을 먼저 정한다. 지원한다면 뒤 선언도 초기화해야 한다. | [라이브러리 추가 조건](libs.md)                                |
