# 전체 프로젝트 검토

원검토 기준 커밋은 `6bbe8cdf7df05ce9aa69cd6ab116f8ccde3fb7f0`, 검토일은 2026-09-26이다. 변경 diff가 아니라 해당 시점의 추적 파일 611개 전체를 검토했다. 아래에 후속 수정 상태를 구분하며, 상세 보고서의 재현·파일별 기록은 원검토 시점을 기준으로 한다.

## 판단

API 본체와 재사용 라이브러리, 작은 연결 데모라는 시드의 목적과 현재 폴더 구조는 대체로 맞는다. 단순 CRUD에서 여러 도메인의 협력·분산 실행으로 읽는 순서도 성립한다. 원검토에서는 단계 간 입력 계약과 공통 유틸·테스트 도구의 경계 조건에서 결함을 확인했다. 기존 검사가 통과한다는 사실만으로 이 부분의 정확성을 판단할 수 없다.

선정한 5개 항목의 수정과 검증을 완료했다. 기존 예제의 계약과 검증을 명확히 하면서 읽기 부담을 작게 유지하는 범위로 한정했다. 나머지 발견은 아래에 구분한다. 실행 환경의 규모·준비 비용과 반복 CI의 비용 대비 효과는 아직 충분히 평가하지 못했다.

## 작업 선정 기준

[README의 변경·검토 기준](../../README.md#기능코드-변경-시-주의사항)을 따른다. 아래 5개 항목은 핵심 예제와 재사용 코드를 기존 소유 지점에서 작게 바로잡는 범위로 선정했다. 회귀 검증은 기존 테스트에서 해당 보장을 직접 확인하고, 바뀐 계약을 소유하는 문서만 갱신한다.

## 완료한 작업

- [x] **API-1 · 중복 좌석 생성 방지** — 기존 SeatmapSchema에서 활성 좌석 좌표의 중복을 거부한다. 같은 행·블록의 중복에 대한 생성·수정 HTTP 회귀 검증을 통과했다. 새 좌석 모델이나 유일성 관리 계층은 추가하지 않았다. [원검토](api.md)
- [x] **API-2 · 0좌석 상영 조회** — TicketsService의 집계가 요청받은 상영 ID마다 결과를 반환한다. 빈 배치·전부 X인 배치의 상영을 실제 workflow로 생성한 뒤 예매 조회의 0건 집계를 확인했다. 내부 집계 결과가 누락되면 500인 기존 검증도 유지한다. [원검토](api.md)
- [x] **TD-01 · 구매 경쟁 테스트의 기대값** — 원 요청의 티켓 목록으로 응답·구매 이력·판매 상태를 대조한다. 검증 함수에 주입한 부분·과다 결과 6개를 모두 거절했고, 실제 4개 복제본의 기본 150회 경쟁도 통과했다. [원검토](tests-demos.md)
- [x] **L2 · SSE UTF-8 처리** — 청크별 문자열 변환을 Node 스트림 디코딩으로 교체했다. 첫 청크 수신 후 나머지 바이트를 보내는 실제 HTTP 회귀 검증에서 한글 원문을 확인했다. [원검토](libs.md)
- [x] **API-3 · 결제 부분 인덱스 사용** — 생성·생성 후 조회·취소 대상 조회의 구매 ID 조건을 기존 부분 인덱스에 맞췄다. 결제 256건에서 실제 사용한 세 필터를 explain해 각각 해당 인덱스로 문서·키 1건을 읽는 것을 확인했다. [원검토](api.md)

검증 스택과 재현용 DB는 종료·삭제했다. 기존 개발 인프라를 reset하거나 기존 사용자 데이터를 삭제하지 않았다. 기존 테스트와 API 문서는 자신의 fixture 데이터를 만들며, 인프라 데이터 전체를 실행 전으로 되돌렸다는 뜻은 아니다.

`pnpm run atoz` 전체, 공유 Restate를 SIGKILL하는 복구 테스트, 장시간 race·benchmark·반복 CI는 이 검토에서 새로 실행하지 않았다. 기존 원격 통과 이력은 참고 자료이며 현재 로컬 커밋의 새 실행 결과로 계산하지 않는다. 모든 입력·장애 조합과 신규 사용자의 처음 설치 경험까지 증명한 검토는 아니다.

선정한 5개 항목의 보장을 기존 테스트와 실제 검증으로 확인했다. 새 파일·의존성·계층을 추가하지 않았고, 변경된 보장은 기존 앱·라이브러리·테스트 가이드에 반영했다. 경쟁 검증 스택은 종료했으며 인프라 reset은 수행하지 않았다. E2E·API 문서 실행·AtoZ 전체는 이번 수정에서 재실행하지 않았다. 보류 항목은 완료 조건에 포함하지 않는다.
