# 사용자 관리

현재 [사용자 서비스](../apps/api/src/services/core/users/users.service.ts)는 생성·조회·수정·탈퇴를 제공한다. 삭제는 soft delete이며 같은 이메일로 재가입할 수 있다. 로그인 세션의 발급·폐기 정합성은 [인증 A2·A3](authentication.md)가 소유한다.

## 결정 필요

### U1. 공통 계정 정보와 예제 프로필 구분

- [ ] 재사용할 사용자 모델의 필수·선택 정보를 정하고 DTO·저장 모델·가입 화면을 맞춘다.

근거: [생성 DTO](../apps/api/src/services/core/users/dtos/create-user.dto.ts)는 이메일·비밀번호 외에 이름과 생년월일을 필수로 요구한다. 생년월일을 여러 프로젝트의 기본 가입 조건으로도 둘지 결정해야 한다.

최소 범위: 생년월일의 필수 여부와 프로필 소유 위치를 정한다. 범용 사용자 속성 저장소는 만들지 않는다. 기존 데이터와 응답의 호환 방식을 함께 정한다.

검증: 필수·선택 필드의 누락·null·수정, 기존 사용자 조회와 가입 화면의 요청이 같은 계약을 따른다.

### U2. 이메일 식별과 중복 처리

- [ ] 이메일의 대소문자·주변 공백 처리와 변경 규칙을 정하고 가입·로그인·수정·관리자 생성에 일관되게 적용한다.

근거: [사용자 저장소](../apps/api/src/services/core/users/users.repository.ts)는 입력된 이메일을 그대로 저장·조회하며 `{ email, deletedAt }` unique index로 중복을 막는다. 이메일 정규화 규칙은 별도로 정의하지 않았다.

최소 범위: 로그인 식별값과 표시값을 구분할 필요가 있는지 정한다. 정규화로 기존 계정이 충돌할 때의 처리와 인덱스 전환을 포함한다. 사용자와 관리자의 계정 공간을 합치는 변경은 별도 결정이다.

검증: 같은 식별값으로 판단한 이메일의 가입·변경이 동시에 일어나도 하나만 성공한다. 로그인·복구도 같은 규칙을 사용하고 탈퇴 후 재가입 계약을 유지한다.

### U3. 이메일 확인과 이메일 변경

- [ ] 가입 시 이메일 확인의 필수 여부와 미확인 계정의 허용 범위를 정하고, 확인·재발송·이메일 변경 흐름을 구현한다.

근거: [사용자 모델](../apps/api/src/services/core/users/models/user.ts)에는 이메일 확인 상태가 없으며 현재 `PATCH /users/me`로 이메일을 바로 변경한다.

최소 범위: 새 이메일을 확인하기 전 기존 이메일을 유지할지, 변경에 재인증을 요구할지 정한다. 확인 토큰의 만료·일회성·재발송 시 이전 토큰 처리와 실제 메일 발송 수단을 확정한다. 메일 연동은 [인증 A5](authentication.md)의 비밀번호 복구와 함께 설계한다.

검증: 만료·재사용·동시 확인·이미 사용 중인 이메일·발송 실패를 처리하고, 새 주소 확인 전후의 로그인과 접근 범위가 결정한 정책과 일치한다.

### U4. 계정 정지·탈퇴와 관련 데이터

- [ ] 계정 정지·해제의 제공 여부, 탈퇴 후 정보 보존·삭제와 재가입 정책을 정하고 계정 상태 전이를 구현한다.

근거: 현재 활성·삭제 구분은 `deletedAt`이며 별도 정지 상태가 없다. 탈퇴는 사용자 행을 soft delete하고 refresh 세션을 회수한다. 구매 기록 등 사용자 ID를 참조하는 데이터의 처리까지 수행하지 않는다.

최소 범위: 본인 탈퇴와 관리자 조치의 허용 범위, 처리 중인 업무·소유 파일의 처리, 탈퇴 재요청의 결과를 정한다. 세션 회수 시점은 인증 A2·A3, 접근 차단은 [권한 R2](authorization.md), 파일 정리는 [파일 F3·F4](files.md)에 연결한다.

검증: 정지·탈퇴·재가입 이후 로그인·갱신·본인 조회·상태 변경 요청이 정해진 결과를 반환한다. 중간 실패나 재요청으로 다른 사용자의 데이터가 삭제되지 않는다.

검증 위치: [users.spec.ts](../apps/api/src/__tests__/core/users.spec.ts), [user-auth.spec.ts](../apps/api/src/__tests__/core/user-auth.spec.ts), [admin-management.spec.ts](../apps/api/src/__tests__/core/admin-management.spec.ts), [사용자 브라우저 흐름](../tests/web/e2e/user-auth-flow.spec.ts).
