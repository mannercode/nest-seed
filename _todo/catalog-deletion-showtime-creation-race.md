# 영화·극장 삭제와 상영 생성의 경합

`DELETE /movies/:movieId`·`DELETE /theaters/:theaterId`와 상영 생성이 동시에 실행될 때의
미해결 정합성 문제다.

## 불변식

커밋된 모든 상영은 활성 영화와 활성 극장을 참조해야 한다.

| 먼저 확정된 작업 | 삭제 결과        | 상영 생성 결과 | 최종 상태                         |
| ---------------- | ---------------- | -------------- | --------------------------------- |
| 상영 생성        | `409 Conflict`   | 성공           | 부모와 상영·티켓이 존재한다.      |
| 부모 삭제        | `204 No Content` | 부모 없음 오류 | 부모는 비활성이고 새 상영은 없다. |

삭제와 상영 생성이 모두 성공해 활성 상영이 삭제된 부모를 참조하면 안 된다.

## 현재 보장하지 못하는 이유

삭제는 상영 참조 확인과 부모 삭제를 별도 작업으로 실행한다. 상영 생성은 MongoDB
transaction 안에서 부모를 확인하고 상영·티켓을 만든다. 두 경로에 공통된 직렬화 지점이
없어 참조 확인 직후 상영이 생성될 수 있다.

영화 경합:

1. 삭제가 상영이 없음을 확인한다.
2. 생성 transaction이 활성 영화를 읽는다.
3. 삭제가 영화를 비활성화한다.
4. 생성 transaction이 상영과 티켓을 커밋한다.

극장 경합:

1. 삭제가 상영이 없음을 확인한다.
2. 생성 transaction이 극장 guard를 갱신한다.
3. 삭제가 극장 갱신을 기다린다.
4. 생성이 상영과 티켓을 커밋한다.
5. 대기하던 삭제가 참조를 다시 확인하지 않고 성공한다.

Application 계층으로 로직을 옮긴 것만으로는 이 경합이 해결되지 않는다.

## 함께 결정할 문제

영화 삭제는 MongoDB 문서뿐 아니라 S3 asset도 정리한다. MongoDB transaction은 S3
삭제를 rollback할 수 없으므로, 경합 해결 시 asset 정리의 실패·중단 복구 계약도 함께
결정해야 한다.

또한 movie 삭제는 `createAsset`·`finalizeUpload`와도 경합할 수 있다. 상영 참조 경합만
고쳐도 삭제된 movie에 asset이 연결되는 문제까지 자동으로 해결되지는 않는다.

현재 정책은 과거·미래를 가리지 않고 상영 하나라도 참조하면 삭제를 거부한다. 이 정책을
바꿀지는 별도 제품 결정이다.
