# 웹 앱

브라우저는 같은 출처의 Next.js 서버로 요청한다. 웹 서버가 API 인증 쿠키를 관리하고 Docker 네트워크 안의 S3로 사진을 전송한다.

## 인증 쿠키와 토큰 갱신

화면에서 아래 코드를 호출하면 웹 클라이언트가 `POST /api/users/login`을 보낸다. 웹 서버는 API에서 받은 토큰을 HttpOnly 쿠키에 넣고 204를 반환한다. [로그인 화면](src/app/login/page.tsx) · [인증 프록시](src/app/api/%5B...path%5D/route.ts)

```ts
await postNoContent('/users/login', { email, password })
```

보호 요청이 401을 받고 갱신 쿠키가 있으면 웹 서버가 토큰을 갱신하고 원래 요청을 다시 보낸다. 같은 프로세스에 같은 쿠키로 들어온 요청은 갱신 결과를 공유하고, 갱신 직후 도착한 요청도 잠시 그 결과를 재사용한다. [쿠키 갱신과 동시 요청 테스트](tests/e2e/user-auth-flow.spec.ts)

| 갱신 결과                    | 브라우저가 받는 응답                                                      |
| ---------------------------- | ------------------------------------------------------------------------- |
| 갱신 토큰이 무효             | 401과 함께 두 인증 쿠키를 지운다.                                         |
| 다른 요청이 이미 토큰을 교체 | 409를 전달하고 쿠키를 유지한다. 늦은 응답이 새 세션을 지우는 일을 막는다. |
| 갱신 서비스 연결 실패        | 502를 반환하고 쿠키를 유지한다.                                           |

## 사진 프록시

브라우저는 `/storage`를 통해 사진을 보내고 받는다. 웹 서버에는 API와 같은 `S3_ENDPOINT`와 `S3_BUCKET`을 지정한다. S3 서명에는 호스트·경로·쿼리가 포함되므로 웹 서버가 허용된 버킷인지 확인한 뒤 발급된 URL을 그대로 사용한다. 버킷이 호스트명에 들어가면 웹 서버에서도 그 이름으로 접속할 수 있어야 한다. [사진 프록시](src/app/storage/route.ts) · [S3 설정](../../infra/compose.s3.yml)
